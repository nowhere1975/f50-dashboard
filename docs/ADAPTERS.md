# 内置路由器适配模块

Traffic Monitor 的本机采样、每日历史、套餐周期、校准、累计和菜单独立于设备接口。当前内置 `zte.f50pro` 模块，已验证设备为 F50 Pro B27。测试中的 Fixture 模块只用于验证扩展契约，不是实际产品支持。

## 模块职责

每个模块实现 `RouterAdapter`，提供以下内容：

| 接口 | 职责 |
|---|---|
| `descriptor` | 稳定模块 ID、显示名称、能力集合和计数保存规则 |
| `matches(model:)` | 判断实际返回的型号，不根据网络别名判断 |
| `request(gateway:)` | 构建只读数据请求，包含该设备所需的请求头 |
| `prepare(gateway:session:completion:)` | 可选的异步鉴权或请求准备；默认直接调用 `request`。需要多步鉴权时由模块实现并返回可取消操作 |
| `decode(_:)` | 将接口响应转换为统一的 `RouterInfo`；不读写 App 的历史和套餐记录 |

注册位置为 `RouterAdapterRegistry.builtIn`。新增模块文件放在 `Sources/F50Dashboard/`，在注册表中添加实例；构建和离线测试会自动纳入该源文件。主程序不需要新增设备型号分支。随后仍需构建和发布新版本；本版没有运行时安装、下载或热加载第三方插件的功能。

设置中的「路由器模块」可选择自动识别、不读取路由器或指定内置模块。自动识别优先探测已确认模块，再按注册顺序尝试其他模块；显式选择只访问该模块的协议。关闭路由器读取后，本机速率和历史仍工作。

## 数据契约

`RouterInfo` 的上传、下载和逐设备计数使用字节，未知值使用 `nil`，合法零值保留。`counterSource` 必须稳定标识原始计数字段，不能因界面重命名而改变。模块没有声明的能力由注册层过滤，界面也按声明决定是否显示信号、接入设备或套餐统计。

能力包括整体累计流量、信号、接入列表与逐设备累计流量。`clientTraffic` 允许模块返回逐设备读数，但本版没有开发逐设备统计页；F50 Pro 模块没有声明该能力，不根据设备总量猜测各客户端用量。

计数规则通常使用 `resettable`：设备可能清零，长时间未读取会使估算质量变为不完整。只有经过验证、确实持续保存的累计计数才能使用 `persistent`；这种模式允许根据重连后的增量接续，但仍检查计数回退和字段变化。当前 F50 Pro 继续使用原来的清零判断规则。

模块的型号校验、数据请求与鉴权准备需要与实际设备验证。准备回调必须且只能完成一次。返回的操作必须能取消全部在途准备工作；共享传输会在取消后丢弃后续回调，不再发起数据读取。准备阶段和最终数据请求均不得将凭证写入历史记录或诊断输出。

## 历史兼容

历史按原有网络身份和日期保存，`routerNetworks` 增加模块 ID、设备型号和显示名称。旧版 `devices`、`f50Networks` 自动补齐归属；原累计、日记录、校准基线、周期起止和提醒记录继续保留。移除模块不会删除其历史，也不会用另一个模块的计数反推旧用量。

套餐记录增加可选模块 ID。首次升级补上来源标识时不重新累计；同一网络、同一周期更换计数模块时保留累计，暂停估算并重建原始基线，等待确认后的校准，避免把不同协议计数直接相减。

本机月度图汇总已确认路由器网络的本机用量。历史只有一种模块时显示其名称（例如 F50 Pro），包含多种模块时合并显示为「路由器」。设备整体计数不混入本机用量。

## 验证入口

```bash
./build.sh test
./build.sh build
~/Applications/F50Dashboard.app/Contents/MacOS/F50Dashboard --adapters
~/Applications/F50Dashboard.app/Contents/MacOS/F50Dashboard --check
```

`Tests/Adapters/main.swift` 提供第二模块、异步准备、自动识别、显式选择、取消、能力过滤、历史保存和套餐累计的离线例子。新增真实模块还需针对其固件补充协议样本与实机验证。
